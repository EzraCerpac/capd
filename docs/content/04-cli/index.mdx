The bundled Mac `capd` command works with the same selected library as the app. It
is useful for quick terminal capture, bulk imports, shell scripts, backups, and
AI-assistant integrations.

For an app installed at `/Applications/capd.app`, the bundled executable is
`/Applications/capd.app/Contents/MacOS/capd`. Add that directory to `PATH` or use
the full path. Follow [installation](/install) to build/install this fork;
`jamiedavenport/tap/capd` installs the upstream project.

Without sync configuration, commands use the local-only library. In an enrolled
library, ordinary commands can attempt a five-second sync flush after local
work. A connection failure does not undo a saved capture. `CAPD_DIR` must match
the app and Agent's root. MCP uses a separate read-only path.

## Capture

```sh
capd add https://example.com/article      # save a link and queue its page content
capd add https://example.com --no-fetch   # save the link without fetching the page
capd add "Remember this" --note "Why"     # save text with a note
capd add https://example.com --title "…"  # provide a title
pbpaste | capd add -                      # capture standard input
capd add https://example.com --wait       # wait for enrichment to finish
```

When standard input contains only URLs, each non-empty line becomes a separate
capture. Otherwise, the complete input becomes one text capture.

`--wait` times out after 60 seconds by default. Use `--timeout <seconds>` to
change it. CLI captures use the same duplicate detection as the app.

## Search and list

```sh
capd search swift concurrency --site swift.org --since 2026-01-01
capd search 'error handling until:2026-06-30'
capd list --limit 20
```

`search` and `list` accept `--limit` and `--format plain|tsv|json`. The
[filter syntax](/search#filter-syntax) is shared with the app.

## Manage captures

```sh
capd rm 12 14       # delete captures by ID
capd refetch        # retry all failed or thin page extractions
capd refetch 12     # retry a specific capture
```

IDs appear in `capd list` and `capd search` output.

## Import

```sh
capd import pinboard pinboard_export.json   # the JSON backup from pinboard.in
```

Download the export from pinboard.in under Settings → Backup → JSON. Bookmarks
keep their titles, notes, tags, and original timestamps; unread bookmarks gain
a `toread` tag. Links already in the library merge instead of duplicating, so
re-running an import is safe.

Imported tags are stored as-is and are never rewritten by automatic tagging.
Imported links skip page fetching;
run `capd refetch <id>` to fetch a page for search later. The same import is
available in the app from the menu bar icon.

## Export

```sh
capd export                    # JSON with saved capture fields
capd export --format markdown  # readable links, notes, and selections
```

JSON includes saved capture fields such as notes, tags, body text, OCR, and
metadata. It does not include image/icon bytes, enrollment configuration,
Keychain credentials, or the shared outbox and sync history. For a restorable
library backup, retain a consistent database and complete asset/configuration
snapshot; see [storage](/app#where-your-data-lives) and [sync](/sync).

## Library sync

```sh
capd sync status      # local JSON status; no network request
capd sync run         # attempt queued delivery and receive remote captures
capd sync deactivate  # pause networking, retain binding and queued changes
capd sync resume      # resume the existing bound connection
```

`capd sync run` requires an enrolled library and waits up to 35 seconds, with
SQLite busy waits potentially adding time. It returns code 3 when another
process owns sync, the library is offline, or attention is required. A successful
local save is separate from server acceptance; inspect pending/rejected work
and note conflicts in the returned state.

Activation is for a prepared library, matching authorized device credential,
and verified server baseline. Stop other writers and complete the backup/import
steps in [library sync](/sync) before using:

```sh
capd sync activate --enrollment /path/to/public-enrollment.json
```

The enrollment file supplies `endpoint`, `binding`, and `deviceID`, not a bearer
credential. Activation does not create a server, device grant, or credential.
Deactivate pauses networking; it does not remove enrollment. Do not remove
configuration or reset device sequences to obtain local-only writes.

## Connect an AI assistant

```sh
capd mcp
```

`capd mcp` serves four read-only tools over the Model Context Protocol:

- `search_captures` uses Capd's full-text search and filters.
- `get_capture` returns one capture with its extracted page text.
- `list_recent` returns the latest captures.
- `ask_cap` answers across the library with numbered capture citations using
  Apple's on-device model.

Register it with Claude Code:

```sh
claude mcp add capd -- capd mcp
```

Or add it to Claude Desktop's `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "capd": { "command": "capd", "args": ["mcp"] }
  }
}
```

Capd's MCP server cannot add, edit, or delete captures. It communicates over
standard input and output; review the privacy policy of the assistant receiving
the results to understand whether that assistant sends them elsewhere.

Even for an enrolled library, MCP opens SQLite read-only, performs no migration,
reads no sync credential, and starts no sync runtime. `ask_cap` depends on an
available Apple on-device model and has no remote fallback.

## Use Raycast

The Capd extension for Raycast is another client for the same local library. It
adds two commands:

- **Capd: Search** searches your captures and accepts the same `site:`, `tag:`,
  `after:`, and `before:` filters as the app. An empty search bar lists your most
  recent captures.
- **Capd: Capture** saves a link or text from a command argument, the current
  selection, or the clipboard. Set it as a Raycast fallback command to capture
  whatever you type into root search.

The extension runs the bundled `capd` command. It locates that command inside
the installed `capd.app`, so the CLI directory does not need to be in `PATH`.
It uses the same selected local library; ordinary commands can also attempt
delivery through that library's configured sync service.

## Check health

```sh
capd status   # queue, capture, storage, and background-helper status
capd doctor   # integrity checks, repairs, and permission status
```

`capd doctor` can rebuild the search index, remove orphaned image files, and
repair the background helper. Use `capd doctor --uninstall-agent` to remove the
helper or `--skip-agent` to check only the library.

Doctor performs repairs; it is not a read-only status command. Its Accessibility
report applies to the CLI process, which can differ from the app's permission.
Use [troubleshooting](/troubleshooting) for connection, icon, and model issues.

## Conventions

- Data goes to standard output; diagnostics go to standard error.
- Exit codes are `0` for success, `1` for no results or unresolved doctor
  problems, `2` for invalid usage, `3` when the store or requested sync is
  unavailable, and `4` when the enrichment helper is not running.
- `CAPD_DIR` overrides the default storage root.
- JSON output is stable for scripts. Existing fields are not renamed, retyped,
  or removed, but new fields may be added. Consumers should ignore unknown keys.
