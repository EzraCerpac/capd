Your Capd library lives in local SQLite databases and asset folders. Optional
enrolled library sync sends captures and verified assets to your configured
server. Capd has no built-in account service, analytics, advertising, or telemetry.

This page lists every network feature in the app.

## Page-content fetching

Capd stores readable page text so search can match more than a bookmark's title.
When a capture comes from Safari, Chrome, or Arc, Capd first reads the rendered
page directly from that browser tab. No additional page request is needed.

For CLI captures, share-sheet captures, dropped links, and Firefox-based
browsers, Capd can fetch the page itself. That fetch uses:

- HTTP and HTTPS URLs only
- an ephemeral browsing context with no shared cookies or persisted website data
- navigation locked to the requested page
- a 15-second timeout and 10 MB response limit

A failed fetch does not discard the capture.

**Control it:** use `capd add --no-fetch` for one CLI capture, or disable **Fetch
page content for link captures** in Settings.

## Website icons

Website-icon generation is disabled by default. When enabled, the Mac Agent
processes eligible saved links, including links received from an enrolled
iPhone. It requests only `https://<original-host>/favicon.ico`, without the
capture path, query, fragment, cookies, authentication or redirects. DNS reveals
the hostname to the system resolver, and the website sees the icon request.
Private, local and reserved destinations are refused before connecting.

The direct numeric connection verifies system TLS trust for the original
hostname before sending HTTP. It bypasses application proxy settings; it does
not promise hostname-triggered VPN activation. This transport supports TLS 1.2.
Sites requiring a proxy, TLS 1.3 or a redirect display a built-in symbol.

Accepted PNG, JPEG and ICO images become static 64-by-64 PNGs without source
metadata. Verified bytes and icon records sync through the configured library
server using the existing enrollment and authorization. Mac and iPhone views
read local cached bytes; they do not fetch icons when a row appears. The iPhone
never contacts the website for an icon.

**Control generation:** use **Load website icons** in Mac Settings. Disabling it
stops new claims; existing verified icons remain readable. The iPhone's
**Show website icons** setting controls display only. Confirmed misses retry
after seven days. Removing the last live link hides its shared icon; retained
blob bytes are not physically erased by that deletion.

## Update checks

At most once a week, the menu-bar app asks the GitHub Releases API for the latest
version number. Updating is always manual.

**Control it:** disable **Check weekly for a new version** in Settings.

## Contextual reminders and link attribution

Contextual reminders read the visible browser URL through Accessibility after
you pause on a page. The URL is normalized and checked against the local capture
database. Unmatched URLs and browsing history are not persisted, and no page is
captured or fetched by this check.

While reminders are enabled, ordinary links opened from Capd include
`utm_source=capd.jxd.dev&utm_medium=app`. This tells the destination website's
own analytics that Capd opened the link and lets Capd suppress a redundant
reminder. Existing campaign parameters are not replaced, and Capd does not add
attribution to local, signed, authentication, checkout, or payment URLs. A local
suppression is also used, so reminder behavior does not depend on the website
retaining these parameters.

**Control it:** contextual observation and link attribution are both disabled
when **Contextual reminders** is off.

## On-device processing

Image text recognition uses Apple's Vision framework. Automatic topic tagging
and Ask Cap answers use Apple's on-device Foundation Models when Apple
Intelligence is available. Captured content is not sent to a model service.

**Control tagging:** disable **Auto-tag captures on device** in Settings. OCR
continues to run locally for image captures.

## MCP and other tools

The `capd mcp` server reads the local library and returns requested results over
standard input and output. Its `ask_cap` tool generates the answer on-device;
the answer, citations, and bounded source excerpts then travel to the connected
client. The server does not make network requests itself. A connected AI
assistant may process those results elsewhere, so its own privacy policy also
applies.

## App security and distribution

Capd runs outside the App Sandbox because reading the frontmost browser tab with
Accessibility and Automation is incompatible with sandboxing. Release builds
use the hardened runtime, are signed with a Developer ID certificate, and are
notarized by Apple.
